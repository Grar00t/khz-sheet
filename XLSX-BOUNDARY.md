# Native XLSX boundary
The writer emits STORED ZIP members and a narrow single-sheet workbook. The reader accepts STORED and raw DEFLATE members, checks CRC, and parses supported workbook/worksheet/shared-string content. It does not implement the whole OOXML schema.
The ZIP loader rejects conflicting local metadata, duplicate/ASCII-case-colliding names, overlapping member extents, nonzero member disk numbers, unsupported flags/encryption, embedded NUL/control/path ambiguity and inconsistent data descriptors. Signed and unsigned 32-bit data descriptors are tested. ZIP64, digital-signature records between the central directory and EOCD, and percent-encoded part-name interpretation are not supported by this narrow profile.
Default compile-time ceilings: archive 256 MiB; member output 64 MiB; total member output 128 MiB; expansion ratio 1000:1; 64 members; 512 name bytes. Archive/part/total/ratio macros in `khz_xlsx_reader.h` can be overridden at compilation. Exceeding resource ceilings returns ERR_LIMIT. Malformed framing returns ERR_FORMAT; selected unsupported features return ERR_UNSUPPORTED. The supplied arena remains an additional allocation limit.
Worksheet/shared-string element matching now uses XML local names, so ordinary prefixes such as `<x:row>`, `<x:c>`, `<x:t>` and `<x:v>` are accepted. Optional cell `r=` attributes are reconstructed from row position and the preceding cell; optional row `r=` attributes advance an implicit row cursor. This is still a bounded scanner, not full namespace resolution or a general XML parser.
Escaped string fields decode the five predefined XML entities, decimal/hex numeric character references, CDATA sections and SpreadsheetML `_xHHHH_` escapes, including UTF-16 surrogate pairs. Malformed string scalars become cell-local `#VALUE!` when a destination coordinate is known; structural XML errors, memory/resource failures and sheet-capacity failures remain fatal.
Cell-local numeric lexical failures no longer abort the worksheet: unrepresentable values become `#NUM!`, malformed numeric/Boolean/shared-string references become `#VALUE!`, and recognized XLSX error literals are imported as native error cells. Unsupported formula syntax is preserved as formula source; recalculation maps unknown functions to `#NAME?`, malformed syntax to `#VALUE!`, and unrepresentable literals/references to `#NUM!` instead of aborting the whole recalc.
Numeric `<v>` text is interpreted exactly as the decimal/scientific value serialized in the workbook. No heuristic Stern-Brocot/continued-fraction reconstruction is applied: `0.33333333333333331` remains that exact rational, because the XLSX bytes do not prove that the author intended `1/3`.
Duplicate-name comparison folds ASCII letters only. It is not Unicode normalization or complete OPC URI equivalence. Directory separators are forward slashes; empty interior segments, dot segments, backslashes, colon, percent, query and fragment characters are refused.
Native load success alone is not sufficient grounds to trust arbitrary untrusted XLSX files. The scanner still lacks a comprehensive namespace-aware grammar, DTD processing, full XML depth/token/relationship budgets, rich-text concatenation and complete shared-formula semantics.
Numeric export uses the existing XLSX conversion boundary and can lose rational exactness. No binary64-free round-trip of arbitrary rational numbers is claimed. Formula text and supported strings have existing tests. The desktop export layer regression-tests a bounded `styles.xml` subset (font/fill/border/alignment/wrap/underline and built-in number-format IDs), but style import, semantic tables, charts and external-application fidelity are not established.
Format reference: PKWARE APPNOTE 6.3.10, sections 4.3.7, 4.3.9 and 4.3.12. SpreadsheetML behavior is tested against the narrow contracts above rather than claimed as general Excel compatibility.
