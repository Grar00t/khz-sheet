# Desktop boundary
The existing WPF shell compiles for net8.0-windows and uses a bounded DataTable view over the native sheet. `WorkbookSession.cs` owns session integration; native semantics remain in C.
The desktop now has semantic Undo/Redo through the ordinary commit path for cell edits and presentation-format edits, case-insensitive Find Next over stored inputs/formula source, a first-column freeze toggle, system-installed font families, preset font sizes, bold/italic, text/fill colors, alignment, cell borders, visual table styling for rectangular selections, an application icon/header mark, and `Copy Proof`. Formatting is desktop-session presentation state only: CSV and current XLSX export do not persist these styles. Table Style is banded presentation, not an Excel table model with structured references, sort/filter, totals, schema or persistence. Transactional rectangular paste, grouped Replace All history, unsaved-change workflow, atomic save, asynchronous import, semantic tables and charts remain absent.
The final Windows desktop build exits successfully with zero C# warnings/errors, and the executable remains running during a three-second startup smoke test before an orderly close. Button-level UI automation was not executed. End-user reliability, accessibility, scroll responsiveness and Arabic/RTL behavior remain separate unverified layers.
