# Desktop boundary
The existing WPF shell compiles for net8.0-windows and uses a bounded DataTable view over the native sheet. `WorkbookSession.cs` owns session integration; native semantics remain in C.
The desktop now has semantic Undo/Redo through the ordinary commit path for cell edits and presentation-format edits, case-insensitive Find Next over stored inputs/formula source, a first-column freeze toggle, system-installed font families, preset font sizes, bold/italic/underline, text/fill colors, alignment, wrapping, built-in number formats, cell borders, visual table styling for rectangular selections, an application icon/header mark, and `Copy Proof`. Explicit cell presentation and visual table banding are serialized into XLSX through a bounded OPC post-process that adds `styles.xml`, workbook relationship/content-type entries, and cell style indexes after the native value/formula writer succeeds. CSV does not carry formatting. Table Style remains banded presentation, not an Excel table model with structured references, sort/filter, totals or schema. Transactional rectangular paste, grouped Replace All history, unsaved-change workflow, managed XLSX open/style import, persisted row/column dimensions, semantic tables and charts remain absent.
The final Windows desktop build exits successfully with zero C# warnings/errors, and the executable remains running during a three-second startup smoke test before an orderly close. Button-level UI automation was not executed. End-user reliability, accessibility, scroll responsiveness and Arabic/RTL behavior remain separate unverified layers.
