# Formula language
The native source parser accepts optional leading `=`, invariant decimal/scientific numeric literals, percentages, parentheses, A1 references with optional `$`, rectangular ranges, unary plus/minus and binary `+ - * / ^`. Range corners normalize. Function names are ASCII case-insensitive; commas separate arguments.
Native functions: SUM, AVG/AVERAGE, MIN, MAX. `^` requires an exact integer exponent within the existing 1024 magnitude ceiling. Noninteger exponent results are refused; 0^0 returns 1/1; zero raised to a negative exponent returns division-by-zero. These are KHZ policies, not an asserted Excel equivalence. No new function identifiers were added in this intervention.
Limits in `khz_formula.h`: 8192 source bytes, 4096 IR nodes, 64 arguments and 64 parser/walk depth. Unary plus participates in the recursion bound. Source offsets are byte offsets. The diagnostic structure still contains English expectation text; stable localized diagnostic keys and full source spans are not implemented.
`khz_formula_set` remains the strict transactional installation path: parse, dependency declaration and cell installation must all succeed before replacement is accepted. Raw formula sources can still enter through the lower-level sheet setter or XLSX import. Recalculation now converts recoverable source-language faults on such stored formulas into cell errors instead of aborting the whole sheet: unknown functions become `#NAME?`, malformed syntax becomes `#VALUE!`, and numeric/range parse overflow becomes `#NUM!`. Structural engine failures such as memory exhaustion remain status failures.
Managed parsing is a separate tree-to-native-IR route, not a demonstrated equivalent grammar for every token. Native installation via `TrySetFormula` remains the preferred text path. Managed parser-wide limits and a full differential grammar corpus remain outstanding.
String, Boolean, error-literal, sheet-qualified and structured-reference formula syntax is not claimed supported. Conditional, logical, text, statistical, lookup and most requested mathematical functions remain unimplemented; XLSX ingestion preserving one of these formulas does not imply native evaluation support.
Tests: `khz_formula_boundary_test`, `KhzExactLiteral`, `KhzFormulaCells`, `khz_xlsx_resilience_test`; bounded dependency walking is also tested through transaction and recalculation tests.
