# Proof contract
ABI 96 uses the existing KHZCELL2 cell-proof domain and predecessor-linked commit entries. Proof inputs include cell address, kind, exact value, text/formula bytes, error/Boolean state, revision and committed metadata. Dirty traversal state is excluded by the existing hashing path.
The intervention does not change proof serialization or include formatting/table/chart metadata. The native recalculation fix restores a cell snapshot when its commit fails, preventing an uncommitted cached value from disagreeing with its proof.
Recalculation is not a whole-workbook transaction: a successfully committed prefix can remain when a later cell fails. A failed individual cell commit is restored. This distinction is intentional documentation of the implemented boundary.
Incremental and forced-full evaluation are compared by semantic values/errors/flags, with each history verified independently. Their proof heads need not match: forced recomputation adds revisions/commits. Equality of different execution histories is not the current proof contract.
SHA-256 integrity chains provide neither confidentiality nor keyed identity authentication. An attacker able to replace the complete history can recompute unkeyed hashes. A trusted external checkpoint is needed to establish full-history truncation/replacement detection. The bounded in-memory commit log and metadata-only ledger are not workbook backups.
